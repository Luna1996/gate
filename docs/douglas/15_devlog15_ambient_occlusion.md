# Devlog #15 - Adding ambient occlusion to my game engine

- 视频: https://youtu.be/3WaLMBiezMU （13:35，2023）
- 类别: 光影 | ⭐⭐ 原创 AO 方案，gate 3.4/3.5 光影升级的首要参考

## 一句话
试遍常规 AO 全失败后，自创「粗粒度占据密度体 + 硬件三线性插值」AO——一次纹理读搞定，比 SSAO 便宜一个量级。

## 内容要点
- **AO 的价值**：接触判断（球贴地 vs 悬空）、结构辨识（墙/顶不分）；没有它场景「平」。
- **两个被否掉的常规方案**（踩坑过程很有价值）：
  1. Minecraft 式逐体素 AO：体素太小，阴影需要 4~8 体素跨度才有效；
  2. SSAO：逐像素平滑渐变与逐体素纯色着色风格冲突；把采样点对齐体素后，随机采样的噪点被放大成闪烁纹理——连「对该体素所有像素的 AO 取平均」都压不住噪声。
- **原创模型**（理论版）：以每点为中心画半径 ~8 体素的球，统计球内实心占比——平面处 50% → 无阴影；墙角处 75% → 越过 50% 的部分映射为暗度。非物理精确但方向正确。
- **实用化**（近似我的近似）：16³ 立方体逐个统计体素数作为密度场；任意点的 fullness 用**相邻立方体中心的线性插值**得到——而 GPU 纹理的硬件三线性过滤天然就是这件事，**零插值代码**。
- **性质与成本**：
  - 插值单调性保证**从不高估**→ 不会出现假阴影；
  - CPU：在本来就要遍历体素做 meshing 时顺手计数（我们则可在构建 brick/tile 时同步算）；
  - GPU：着色时**单次硬件过滤纹理读**；对比 SSAO 的整个后处理 pass + 8+ 次随机采样读。
- 顺带：OpenGL→WebGPU 迁移；compute shader 地形生成；vertex pulling 改进 greedy meshing → 三角形再降 15-20%。

## 对 gate 的启示
- **这是 gate 3.4 环境光 / 3.5 光影升级里 AO 的首选方案**：
  - 密度场 = 每 cell（或 8³/16³ 粒度）的占据计数 → 一张小 3D 纹理（R8/R16 即可）；
  - DDA 命中后按世界坐标采样这张纹理（硬件 trilinear），>0.5 部分映射为暗度，乘进直光/环境光；
  - 成本几乎为零，且与「逐体素纯色 + 直光阴影」的观感自洽（比 SSAO 干净得多，他两条踩坑记录我们不必重踩）；
  - 密度计数可在现有 builder 构建 tile 时顺带产出，编辑时局部更新——与增量上传管线兼容。
