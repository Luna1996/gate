# Devlog #17 - Adding ray tracing (back) to my game engine

- 视频: https://youtu.be/aY4Zet_C9Zs （12:29，2024）
- 类别: 光影/基础渲染 | ⭐⭐⭐ 当前架构奠基集，与 gate 路线同构，基准 GPU = 1660 Ti

## 一句话
抛弃光栅化回归纯 ray marching：为的是逐体素独立颜色+法线；用 4³ brick 树 + 64-bit mask 把内存读压到极限，1660 Ti 上主射线+阴影射线 7ms/帧。

## 内容要点
- **为什么回归 ray marching**（对 gate 有决策参照价值）：
  1. 光栅化下材质系统是 Minecraft 式的「材质 + 16×16 纹理」——拉远看整片山只有一个颜色，细节尽失；
  2. 导入外部体素模型必须把任意调色板映射到有限材质集，效果差、演示场景难做；
  3. **逐体素独立颜色 + 逐体素法线**是真实感光照的根本，ray marching 直接读体素数据，光栅化则每个独立体素都要生成三角形 → 效率崩。
- **逐体素法线 = "secret sauce"**：Gabe Rundlett / John Lin 引擎观感好的秘密——表面朝向决定明暗，让形状可辨、光滑不方块。
- **内存读是头号敌人**：GPU 内存极慢，缓存又吃寄存器（同样糟糕）；每次下钻八叉树 = 8+ 次内存读。
- **两个核心解法**：
  1. **Brick 树**：父节点分 4³=64 子块（非八叉树 2³）→ 层数更少、读更少；
  2. **64-bit occupancy mask**：每 bit 对应一个子块；射线读一次 mask 进寄存器，之后用位运算查子块空实，**最多 10 步不需要任何内存读**。
- **实测**：Teardown 城堡地图，主射线+阴影射线 **7ms/帧 @ GTX 1660 Ti**——还没做 ray marching 循环优化、没有 depth prepass，纯靠跳空+mask，且他怀疑当前是 compute bound，还有余量。
- **集显策略**：不用混合管线了——**直接降分辨率渲染**（"体素世界低分辨率反而可爱"）。
- 其他：支持任意数量非网格对齐对象、LOD；删了 11,000+ 行旧代码。

## 对 gate 的启示
- **架构同构验证**：gate 的 5-level bitmask brick map（16³ cell/tile、palette u8、位图跳空）在思路上与他的 brick tree + u64 mask 是同一家族；他的「进 brick 后用 mask 寄存器连续步进、零内存读」是 gate WGSL 可以进一步压榨的点（现在 gate 每 cell 级查询是否仍有 buffer 读？）。
- **1660 Ti 7ms 主+阴影射线**是 gate M2 基线（1660, 1080p60）最有力的外部可行性证据——阴影射线在预算内，3.5d 软阴影采样调优有余量。
- 「逐体素法线让观感质变」呼应 #22 的教训：gate 不存法线，但**运行时隐式生成法线**（#22）+ 命中面插值是通往他这种光滑观感的路径，值得列入 3.4 环境光升级的评估项。
- 「低端卡=降分辨率」与 gate 的 RenderScale 半分辨率决策一致，可放心坚持。
