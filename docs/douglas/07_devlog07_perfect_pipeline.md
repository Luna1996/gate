# Devlog #7 - The PERFECT voxel rendering pipeline (and online demo)

- 视频: https://youtu.be/IFUj53VwYvU （14:40，2023）
- 类别: 基础渲染 | ⭐ 渲染管线成熟形态，发布浏览器 demo

## 一句话
重构 parallax ray marching 的数据侧与提交侧：页式 GPU 分配器统一资源 + 只存表面盒 + 三重 CPU 剔除（最终只画 20-40% 三角形）+ 场景不变不重算阴影。

## 内容要点
- **旧方案瓶颈**：每 256³ chunk 一张 3D 纹理 + 朴素 meshing，不可扩展。
- **GPU 内存分配器**：所有体素对象共享「1 个大 vertex buffer + 少数大纹理」。抽象：资源 = 固定大小 page（buffer 段或 3D 纹理立方块）；空闲/占用页存成位串，按 64 页一组位运算找连续空区——极快，特别适合大量同尺寸分配。零开销抽象。
- **表面盒生成**：从八叉树顶层向下搜实心区域 → 标记表面 8³ 盒为可见，否则递归下层。GPU 只存可见表面盒：
  - 盒内 8³ 体素 → 紧打包进共享 3D "materials map" 纹理；
  - 盒的 6 个面 → 面缓冲，每面 16B（4B 指向 materials map + 12B 四角位置，每角 3B）。
- **三重 CPU 剔除**（合计只渲染 20~40% 三角形，顶点着色器调用大省）：
  1. **视锥剔除**：投影空间按 chunk 尺寸外扩，chunk 四角全在外 → 整块跳过；
  2. **八分体剔除**：chunk 完全在相机某一侧 → 该侧朝向的面全部不画（必不可见）；
  3. **朝向剔除**：面法线背对相机 → 不画。
  - 全部构建在 gl MultiDraw 之上：一个大 buffer + 子区间列表 + **单次 draw call**（网页上 GL 调用要走 JS，驱动开销尤其致命）。
- **阴影按需更新**：仅当场景变化（编辑/销毁/chunk 加载）才重算 shadow map；几何分两遍（大静态场景 + 小动态物体），移动阴影投射体也保得住该优化 → 大多数帧不跑昂贵光照。

## 对 gate 的启示
- 「场景不变则光照不重算」是我们 DDA 每帧全量重算可以对照的方向：gate 的直光/阴影目前每帧重跑，静态场景下有帧间缓存机会（存储 texture 复用 + dirty 标志），属于 1660 降档储备池。
- 页式分配器 + 位图找连续空页，与 gate 的 pow2 bucket free list 同族，可互相对照补强。
- 面向相机的三重剔除是 raster 思路；gate 的对应物是「AABB slab 相对标尺 + 空 ray 0 步」，但「朝向/八分体预判」思想可在 DDA 起点预判上省步数。
- 他的阴影是 raster shadow map；gate 若坚持 DDA 阴影射线，「只在脏时重算」+「静态/动态两遍」两条优化照搬即可。
