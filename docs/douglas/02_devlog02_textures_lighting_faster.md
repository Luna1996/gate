# Devlog #2 - Textures, lighting, and MUCH faster rendering

- 视频: https://youtu.be/PfaNQLs6E94 （7:39，2022）
- 类别: 基础渲染

## 一句话
加材质/纹理/初级光照，重点是通过 SVO 布局重排把渲染耗时砍半（7-10ms → 3.5-4ms @ GTX 1070）。

## 内容要点
- **材质系统**：每体素 16-bit 材质 ID；纹理 = 小型 3D 颜色数组，**按 3D 平铺（tiling）覆盖整个体素体积**——免显式 UV、内存几乎不涨。为将来光照/透明参数预留字段。
- **LOD**：八叉树天然支持——遍历提前停在目标层即可，实现极简；但实测对渲染提速不明显（八叉树空分支跳跃本身已把大半工作省了）。
- **阳光阴影**：命中点向太阳方向再投一条射线，不通即阴影——因为 raymarch 已有，几乎白送。teapot 模型用 voxelizer 工具导入。
- **逐体素光照（非逐像素）**：从体素中心投 1 条射线，对暴露面取平均光照值 → 强调整体形状感、弱化"体素感"，观感更好。
- **多物体遍历重写**：旧法每射线遍历所有 object 的 AABB + 按入射深度排序（GPU 不能动态分配，只能固定 4~8 个）；新法**按"最短步进距离"动态切换目标 object**，射线可穿过无限个物体（代价：切换时仍 O(n) 扫描，留待加速结构）。

## 性能优化核心（本集最重要）
- SVO 每层布局原为：LOD 数据 + octant 类型 flags + 满八叉体数据 + 稀疏八叉体 position offsets——下钻时需动态计算 offsets 区的索引。
- 改法：**把 position offsets 与材质数据对齐排布**，直接跳到目标 octant，省掉 buffer 读和循环；代价是树体积 +30~50%（padding）。
- 结果：**渲染耗时直接减半**；再叠加位运算小优化。结论：消灭 buffer 读取和 for 循环是 GPU 侧最大收益来源。

## 对 gate 的启示
- 3D 平铺纹理方案是"表面纹理否决"裁决的现成参考——若未来要表面细节，这是不用改管线、不加 mesh 的低成本路径。
- 「逐体素平均光照」值得作为我们 DDA 输出着色的一个廉价观感选项（与调色板直出兼容）。
- 「按最短步进距离在对象间切换」对多 brick/tile 间穿行的 DDA 主循环同样是正确抽象。
