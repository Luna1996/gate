## 0. 用户的验收口径（本轮定死的）

- **帧时（不是帧率）**：开了 vsync 之后"每帧的**工作量**"必须稳定在 **10 ms 以下**，含相机
  旋转 + 移动，且**无尖峰**（一次 >16.7 ms 就是掉一帧）。
- **不允许假优化**：不许调低当前画质档位（GI 分辨率 / 分帧 / 候选数 / 降噪质量 / 视距 / 像素大小），
  也不许做其他损坏画面质量的 trade-off。
- 判断"卡在哪一侧"必须看 `--features profile` 的**逐 pass GPU 均值** + `RENDER 帧周期`
  （只这两条；帧率数字被 vsync 掩盖）。

## 1. 本轮做完的事（都已落盘、已编译、已过单测）

### 1.1 `STREAM 流式装载` 8.70 → **0.42–0.50 ms/帧**

`gate-app/src/infinite_cubes.rs`：

- 卸载扫描的闸门里去掉恒真的 `grid.chunk_count() > cap`（`cap` 是按**全分辨率 1 MiB/块**估的，
  而粗档块只有几十 KB ⇒ "常驻 > cap"是长期状态、闸门恒开、每帧白扫 O(常驻)）。
- 加 `VolState::trim_idle`：超容扫描**空手一次就空闲**（需求表重建 / 窗口移动时清）。
- 需求集 / 待挂载集**缓存**（`demand_set` / `ready_set`，需求表重建时同步），不再每帧现折两个 HashSet。

### 1.2 `RESID 常驻调度` 4.70 → **1.38–1.57 ms/帧**（本轮的主要交付）

上一轮给 `plan_residency` ①⑤ 加的是"序号变了就重算"的闸门 —— 而流式世界里相机**一动就每帧都有**
挂载 / 卸载 ⇒ 闸门恒开，仍是每帧一遍 O(常驻)（常驻 ~1.8 万块）。改法：

- `gate-voxel/src/volume.rs`：`VolumeGrid` 新增**常驻集变更日志** `resident_log`（`ResidentChange
  { c, mounted }` 追加表，与 `resident_seq` **逐条成对**；封顶 `RESIDENT_LOG_MAX = 16K` 条，满了
  整段清空并抬 `resident_log_epoch`）。访问器 `resident_log_from` / `resident_log_len` /
  `resident_log_epoch`；三处变异点 `mount_chunk_tree` / `unmount_chunk` / `take_chunk` 各推一条。
- `gate-render/src/brickmap/upload.rs` 的 `plan_residency` ①：
  - **增量**：只消费游标之后那几条 —— 挂载的走 `ledger_note`（首次记账 / 刷字节），卸载的
    `note_gone` + **就地 `builder.evict` 归还 GPU 块**（这就是 ⑤ 的增量形式，⑤ 只剩每 240 帧兜底）。
  - **退回全量扫描**的四种场合：首次（`ledger_ready`）、日志被清空（代数变了）、日志尾部长度与
    `resident_seq` 增量对不上（世界被换掉 / 两者脱节）、每 `LEDGER_SWEEP_FRAMES` 帧的兜底。
  - 删掉 `ledger_busy` 与 `sync_seq`（④⑤ 的账目本来就是就地更新，不必下帧重算；`sync_seq` 被
    增量路径取代）。
  - ③ 里补上"本帧被编辑的 chunk 刷驻留字节"（旧写法靠"有编辑就全量重算"覆盖这一点）。
  - ⑦ 取证：`is_resident`（哈希探测）与距离判据换位 —— 距离是 O(1) 算术，放前面即免掉
    每帧常驻块数量级的哈希白账（0.60 → 0.08 ms）。
- `gate-render/src/brickmap/residency.rs`：`recent_desc(keep)`（全排序 O(n log n)）→
  **`recent_top(keep, n)`**（`select_nth_unstable` 只取前 n；`n ≥ 候选数` 时连选都不做）。
  消费端只 `take(cap)`，而 `plan` 会按距离重排 ⇒ 顺序本来无意义（键是 (Reverse(last_use), x, y, z)
  全序，截断的集合唯一）。
- 需求集逐块循环加早退：**流式世界 + 已在最细档**（`cur == BRICK_FACTOR`）⇒ `lv = min(want, cur)`
  恒等于 `cur`、`plan` 会把它滤掉 ⇒ 连距离都不必算。
- 新增单测（`gate-voxel/src/volume.rs`）：`resident_log_pairs_with_seq`（逐条成对 + 越界游标按空段）、
  `resident_log_overflow_bumps_epoch`。

## 5. 复现口径与陷阱（省下一次踩坑的时间）

**跑一次量测**（约 5–10 min，含 release 重编译）：

```powershell
Copy-Item data\config.toml "$env:TEMP\gate-config-backup.toml" -Force
(Get-Content data\config.toml -Raw) -replace '"video/vsync" = true','"video/vsync" = false' |
  Set-Content data\config.toml -NoNewline       # vsync 必须关，否则看不出余量
$env:GATE_BENCH="orbit"                          # static 是对照（相机不动）
$env:GATE_LOG="info,gate=debug,gate_app::debug_menu=debug"
cargo run --release --features profile
# 跑完（看到 3–5 行 GPU 逐 pass）后停掉，再从 logs\latest.log 取数
Copy-Item "$env:TEMP\gate-config-backup.toml" data\config.toml -Force   # 必须还原
```

读日志：`Select-String -Path logs\latest.log -Pattern 'GPU 逐 pass|RENDER 帧周期|RESID 常驻调度|STREAM 流式|MAIN 主世界调度'`。
`SysTimer` 的每 60 帧一行是**均值**，尖峰看 `RENDER 帧周期` 的逐行最大值。

**陷阱（都真踩过）**：

- **空世界跑出来的数字全是假的**：LOD 作废 ⇒ 回落 Anvil ⇒ 主世界只有 75–99 块、远场空着 ⇒
  "帧时 6 ms / 163 fps"是幻象。**先确认 `data/lod/mc_map.lod` 命中**（日志里没有那条
  `LOD ... 是别的地图 / 存档改过了 → 作废`），再看帧时。
- **机位在空区跑出来的数字同样是假的（2026-09-28 亲历）**：`data/config.toml` 的 `[camera] eye`
  是**上次退出时保存的**，而上次可能停在海床下方 / 世界外 ⇒ 全部射线空走。判据 = `REQ[…用途戳
  **0 chunk**]` 且 `GPU 逐 pass 合计 ≈ 0.5 ms`；此时**即便 `STREAM[v0 …]` 显示世界已填到 18202 块
  也是假的**（世界装上了，但射线没打到它）。修法 = 把 `[camera] eye/yaw/pitch` 改成城市上方俯视
  机位（`eye ≈ [1840, 1776, −32]`、`yaw = 0`、`pitch ≈ −0.3`）。**改这个文件必须用编辑器
  （Read+Edit），不许用 shell 重定向**（用户明令）。
- `gate_dda_face` 与"逐面缓存"的数字只有在**逐面 pass 真的在派发**时才有意义；拿 `DDA_*`
  诊断开关做 A/B 时，画面会被拆掉 ⇒ 不要用那时的 pass 数字去比"优化效果"。
- 本仓**禁止 debug 构建**（`build.rs` 会 panic），一律 `--release`。
- 改 `assets/locales/*.toml` 需**重新编译**（`rust-i18n` 编译期 codegen）。
- 提交前跑一遍：`cargo clippy --release --workspace --all-targets -- -D warnings`、
  `cargo test --release -p gate-voxel -p gate-render`（本轮跑过：33 + 2 + 20 全绿）。
