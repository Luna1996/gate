# Devlog #10 - Adding SNOW and MODEL IMPORTS

- 视频: https://youtu.be/XNtdYQLiGbA （13:32，2023）

## 一句话
下雪 demo：渲染/模拟分离（客户端 GPU 粒子 + 服务端 tick 积雪合批）+ g-vox 模型导入（20 小时 WASM 联调）+ 级联阴影图。

## 内容要点
- **雪的职责分离**：
  - 客户端：空中飘落纯视觉——CPU 只负责生成（射线投射保证只落在表面，不穿树/洞），**每帧位置全由 GPU 算**（~6000 片），CPU 零逐帧负担；
  - 服务端：地面积雪是真体素——挂在 server tick（~40/s）事件里生成。
- **小编辑合批**（性能关键课）：初版每片雪单独 place → 卡。根因：他的引擎为「低频大块更新」设计，不擅长高频小更新。修法：攒 20-30 片**一次性提交**——把 N 个小更新合并成 1 个大更新。
- **模型导入**：用 Gabe Rundlett 的 g-vox（C++ + Rust binding）；为了 WASM 里跑 C++ 花了 20 小时联调（2 次编译器 ICE，一度放弃，最后差 100 行）。Ace of Spades 地图 16x 缩放导入（16x = Minecraft 步速对齐他的世界尺度）；导入的块仍可逐体素编辑。
- **CSM 级联阴影图**：近处高分辨率、远处粗分辨率——远物也有影但不吃内存。
- 工作法：kanban 看板管理任务。

## 对 gate 的启示
- **「引擎吃大不吃小」与 gate 同病同解**：gate 的上传预算/脏区间管线同样偏好合批；任何高频产生小编辑的特性（雪、雨、粒子沉积）都应带积攒层（攒 N 个或 T 个 tick 一次提交）。
- 客户端 GPU 粒子 + 服务端真体素沉积的职责切分，是 gate 沙盒氛围特效（雪/雨/萤火）的正确模板：视觉走 GPU buffer，不影响 DDA 数据。
- CSM 是 raster 思路；gate 的对应问题是「阴影射线步数预算随距离衰减」——远处降低射线预算（反正分辨率不足），与 3.5d 软阴影采样调优同向。
- 外部模型导入走成熟库（g-vox / MagicaVoxel .vox 生态）——gate 的 MagicaVoxel 资产管线可复用同一生态。
