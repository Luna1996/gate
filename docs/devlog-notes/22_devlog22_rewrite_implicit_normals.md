# Devlog #22 - Grass, textures, and a new codebase

- 视频: https://youtu.be/YTZBFz3Et40 （18:32，2024）
- 类别: 基础渲染 | 完整代码库重写复盘（8 月→1 月）

## 一句话
推翻重来的全景集：WASM mod 模式破产 → Rust 内核 + C 前端 API；显式逐体素法线被证明是编辑语义的毒瘤 → 改为运行时隐式生成 + 三平面贴图一次性烘焙；草叶=后合成装饰层；顺带最简体积光。

## 内容要点
- **WASM mod 的两个死结**（导致弃用）：
  1. 调试体验差、wasm 引擎兼容参差；
  2. 独立地址空间——跨边界只能传数字/字节数组，共享对象+GC 语义极难设计，连「编辑体素数据」的 API 都暴露不出来。
- **per-voxel normals 的教训**（重要架构反思）：显式存储法线让光照好看，但删除/填充/复制区域时邻接体素法线全要重算，语义定义不清 → 连「区域复制」这种基本操作都做不出来。**新决策：法线运行时隐式生成**（近似算法），不存储、随上传计算。
- **新架构**：Rust 内核（体素/图形/物理，吃满 SIMD）+ **C 前端 API**（实体/业务逻辑/mod，同地址空间动态链接）——模仿 Unity 的 C++ 后端 + C 脚本层；mod 作者与引擎作者用同一套 API。
- **数据结构**：沿用 64-tree（4³ 合并，即常说的 con tree）但撕掉法线字段腾出位宽；区域 fill/copy + CSG（球/柱/环光栅化画入）全部**直接在稀疏组上操作**，~4-5k 行 Rust，实时执行。
- **图形新特性**：
  - 上传时算一次表面法线 → **tri-planar mapping** 贴高分辨率 PBR 纹理，法线+颜色**烘焙进 GPU 侧体素模型并缓存**（一次性成本）；
  - CSG 面置换（凹凸砖面）；
  - **草/叶=装饰（decorations）**：上传时按材质生成辅助 buffer（草叶簇），逐帧预先光栅化后**合成到 ray marched 结果上**——风动的是装饰，体素不动（参考 acerola 等人的草地教程）；
  - 吸收性透明（玻璃/冰）；
  - **最简体积光**：树间光柱，随走动变化。
- 现状：仅太阳+环境光；下一步 GI、物理移植、无限世界生成。

## 对 gate 的启示
- **隐式法线生成**是我们做「逐体素平均光照/更平滑着色」时绕开数据结构污染的标准答案——gate 调色板只存颜色，未来要平滑光照时不该往调色板塞法线，而是 GPU 侧按表面邻近关系现算。
- **装饰层合成**是「树林/草丛不加 DDA 命中代价」的现成方案（对应 demo 场景 170 棵树、L4 水晶簇的降档思路）。
- **最简体积光**就是 v3.5c god rays 廉价版的实机参照——他也是在光栅/后合成侧做的，没走完整介质散射（那归 P9.8）。
- 「编辑语义必须和数据结构一起设计」的教训正面印证 gate 的硬约束（编辑驱动的可变叶 + 增量元数据维护）。
