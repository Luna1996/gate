# Devlog #29 - Coding a character controller

- 视频: https://youtu.be/HlCVvG7_HFY （12:01，2025）
- 类别: 玩法

## 一句话
运动学角色控制器：接触面裁剪速度 + Quake 式自动上台阶（改造为逐体素增量试探），相机垂直位置用临界阻尼弹簧防晕，全部只用公共 C# API 写成。

## 内容要点
- **rigid body vs kinematic 控制器**：前者把角色当真刚体（Rocket League 式），难加「上台阶」这类非牛顿自定义运动；后者每帧用**碰撞查询**写自定义移动——他选运动学：动作自由度大、且客户端可跑（刚体模拟只在服务端，而角色操控需要客户端即时响应）。
- **基础移动循环**：碰撞检测拿接触法线 → 每个接触视作平面，把期望速度**裁剪到与所有平面相切或背离**（带约束的二次规划，几个 for 循环可解）→ 沿裁剪速度 sweep hitbox（体素世界用略小于 1 体素的步进）→ 撞到新东西再裁剪 → 循环直到模拟完整个 time step。
- **上台阶**（Quake 源码取经）：常规滑动 + 「上移 step height → 平移 → 落回」备选路径，落地且走得更远则采用。他的两个改造：
  1. 不只试整档 step height，**按 1 体素为增量试多档**（否则进低于 step height 的门会过冲撞门框）；
  2. **找到首个保持全速的可行解即停**（不等最优解），省碰撞查询。
  下台阶免费获得：每种运动路径（包括不上台阶）结尾都尝试向下探一整档 step height，贴地行走。
- **防晕相机**：第一人称下逐体素「瞬移」极晃 → 相机垂直位置建模为**阻尼弹簧**（偏低/偏高施加加速度+阻力，阻力系数保证临界阻尼 → 永不过冲、指数收敛）。
- **API 架构**（他最自豪处）：`character mover` 不可变值类型，每帧新建；所有 helper（摩擦/弹性/sweep/单步试探）**返回副本、从不原地修改**；链式调用组织整帧移动；下游可用扩展方法扩展。**整个控制器只用引擎公共 C# API 完成**——下游用户自己就能写出来，是对引擎架构的早期验证。
- 材质交互：脚下体素的摩擦/弹性直接复用刚体系统代码。

## 对 gate 的启示
- 沙盒模式从「浮空相机」到「能走动的角色」时，这套运动学循环 + 逐体素增量试探就是施工图；6 连通碰撞查询与 gate flood-fill 邻域语义同源。
- **不可变值类型 + 返回副本的 API 风格**与 Rust 所有权模型天然契合，gate-ui / 编辑器 API 设计可借鉴（「每帧新建 mover、链式算完」避免可变状态纠缠）。
- 防晕弹簧相机是任何第一人称/跟随相机的标配细节。
- 「只用公共 API 实现完整功能」作为 API 成熟度验收标准——gate 的 gate-ui 组件库（TODO 2.7a）可用同一标准检验（耗时面板应能用公共组件拼出）。
