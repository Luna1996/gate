# Devlog #5 - Adding MULTIPLAYER NETWORKING with WebRTC

- 视频: https://youtu.be/bQXM0QSlsqs （13:36，2023）
- 类别: 其他 | ⭐ 网络：浏览器端点对点体素多人

## 一句话
浏览器内 P2P 多人：WebRTC（ICE 打洞）+ Go 写的信号服务器牵线；游戏逻辑整体搬到内部「游戏服务器线程」，单机玩家也只是一个本地客户端 → 单机/多人代码路径统一。

## 内容要点
- **选型**：浏览器内只有 HTTP/WebSocket/WebRTC 三条路；HTTP 太慢、WebSocket 不支持 P2P → WebRTC（Discord/Teams 同款）。
- **P2P 两大难题**：互相发现 + 穿防火墙。流程：双方先向信号服务器登记 → 服务器互发连接信息 → ICE 协议直连，之后流量不过服务器。
- **信号服务器**：Go 写的 REST API，注册账号/发布房间/转发 WebRTC 握手信息。
- **架构关键**：引擎内部跑一个 game server 线程，本地玩家也以客户端身份连接 → 主机玩家只是"另一个客户端"；客户端逻辑对连接类型（本地/WebRTC）做抽象。
- **网络平滑**：远程对象位置插值消除更新抖动；后续 #9 加客户端预测（编辑先行显示，服务器确认前本地可见）。
- **体素同步**：八叉树数据放服务器侧，多客户端共享；放置/销毁即时同步。

## 对 gate 的启示
- 「内部服务器 + 一切客户端」模型与 gate 的编辑器/模拟分离哲学一致：模拟状态单点持有、渲染与输入只是客户端。
- 体素增量同步：#9 演进为服务器自动追踪脏区域隐式推送，与 gate 的 dirty tile 队列同构，未来联网成本极低。
