# Devlog #25 - Prototyping physics and procedural generation

- 视频: https://youtu.be/pY7Y2pSCnGo （9:26，2025）
- 类别: 物理 | 过渡集：v2 不稳定 → 2D 玩具引擎试验场

## 一句话
物理 v2 堆叠不稳 → 开源 2D 玩具引擎 Rigid Pixels 模块化试算法；地形生成曲线对齐 Minecraft；社区协作者一夜造出建造系统+房子。

## 内容要点
- **社区协作**（C 前端架构的红利）：另一位体素 YouTuber Kelvin 在 C 侧一晚实现 Minecraft 式建造系统（立方/球/圆柱）并建了一栋房子——亚米级细节（细栅栏柱、灯、椅）、反射地板、放置时可调染色、灌木雕刻得不方块。作者的梦想：不会编程的人也能建造。
- **物理 v2 的缺陷清单**：叠 1-2 个盒子就抖散；角落堆大量对象会爆炸/嵌墙/求 解器失效——Teardown 没这些问题，所以他也必须能解决。
- **Rigid Pixels**（开源 2D 玩具引擎，GitHub）：模块化试不同碰撞检测算法与求解器组合，找最稳方案。「tumbler」测试场景：固定空腔立方体内 49 个小方块，求解器能把力跨多层传递、最终沉降不爆炸。学到的东西后来进了 #26（TGS + warm starting）。
- **地形生成**：曲线特意调成与 Minecraft 一致（大山丘/沟壑/3D 悬垂）；重点是 **API 设计**——高性能且可扩展，目标是让用户写自己的地形生成器。下一步：生物群系（草色/沙/雪）+ 地表物件（树/石/花）。

## 对 gate 的启示
- 「玩具引擎先行」方法论第二例（#20 建议→#25 实践→#26 收获）：gate 未来数值算法（应力/流体）也应先在 2D 小环境里定算法再进主引擎。
- 建造系统从 C API 侧一晚成型 = 前端 API 设计成功的标志。gate 的 gate-ui/编辑 API 若能让「关卡作者」在短时间内拼出可玩关卡，就算达标。
- 地形生成器「多尺度曲线 + 可插拔生物群系 + 用户可扩展」的 API 分层，对应 gate 沙盒模式的场景生成器设计（demo 场景的手工 paint 函数未来可数据化/参数化）。
