# Devlog #21 - Creating a modding system with Rust and WebAssembly

- 视频: https://youtu.be/fvxOI0nQsTA （11:52，2024）
- 类别: 其他 | ⭐ 模组系统：wasm 沙箱 + 宿主 trait 导出

## 一句话
模组 = Rust 编译的 wasm 模块：沙箱安全（独立地址空间）+ 平台无关（一次编译全平台跑）；宿主引擎定义 trait，宏魔术让 wasm 插件直接调用；支持热重载、输入重映射、egui 画 UI。

## 内容要点
- **为什么 wasm**：安全（沙箱化，杜绝 Minecraft 模组病毒式事件）+ 跨平台（编译一次，Windows/Mac/Linux/浏览器通吃）。
- **宿主-插件通信**：引擎内部实现 trait（如帧时间查询），rust 宏生成胶水让 wasm 插件像调本地方法一样调用宿主 trait。插件侧定义依赖 trait 的对象类型即可。
- **热重载**：引擎监控 wasm 文件变化，自动重载新版本，不用重启。
- **输入系统设计**：模组只声明「动作 + 默认键位」，引擎负责用户重绑定 UI 与存储；模组不接触绑定细节。官方 player controller 模组本身就是用这套 API 写的（吃自己的狗粮）。顺带支持手柄。
- **模组可画 UI**：准星/底部文字由模组绘制；完整 UI 用 egui，为将来建筑/背包系统铺路。
- 暂停菜单/模组管理界面（列表 + 描述 + 加载 wasm 文件）。

## 对 gate 的启示
- 「宿主 trait + 宏导出」模式是 gate 未来关卡脚本/自定义元件 API 的现成蓝本；wasm 沙箱与 gate 的「玩家创作」定位（可编辑电路世界）契合。
- 「模组只声明动作语义、引擎管绑定」与 gate 元件连接语义的「类型驱动规则」裁决同思路：语义与机制分离。
- 当前优先级低：gate 先完成单机玩法闭环，P12 平台化阶段再评估。
