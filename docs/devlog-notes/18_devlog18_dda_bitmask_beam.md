# Devlog #18 - Doubling the speed of my game's graphics

- 视频: https://youtu.be/P2bGF6GPmfc （13:01，2024）
- 类别: 基础渲染 | ⭐⭐ 对 gate DDA 性能最有直接借鉴价值的一集

## 一句话
三项优化把 ray marching 帧时砍半（集显 120→60ms）：brick 内 DDA 化、编译期方向位掩码预过滤、beam 多分辨率保守起步。

## 内容要点
背景：他从光栅化方案**回归 ray marching**（#16 说 raster 到顶了），树分 4³ brick（64-bit occupancy mask + 数据段），要为透明/反射/体积雾腾预算。

1. **brick 内 DDA 化**（120→100ms）
   - 旧法每步做 ray-box 求交：重算 X/Y/Z 三分量 + 乘除（多周期）。
   - DDA：存三轴 tMax，每步只更新最短的那个分量 + 加法——单分量、纯加减。
   - **关键限制（他自己承认没解决）**：DDA 只适用于固定尺寸网格；**跨 brick/跨树层级仍得用 ray-box 求交**。他公开求「跨层级 DDA」的方案。
2. **方向位掩码预过滤**（100→80ms）
   - 编译期生成查找表：对每种（进入位置 × 主方向组合）预计算「这条射线可能命中的体素位掩码」；
   - 运行时：brick 占据 mask AND 方向 mask = 0 → 整个 brick 直接跳过（几条 GPU 指令）。
3. **Beam 优化**（80→60ms）
   - 先低分辨率跑一遍射线，全分辨率射线以「周围 4 个（斜向布局 6 个）低分辨率射线的最小距离」为起点 → 全分辨率射线平均行程大幅缩短；
   - **保守性证明**：低分辨率 pass 限制步进深度，保证「任何大到可能从低分辨率射线缝隙漏掉的体素」必被某条低分辨率射线命中 → 输出与非 beam 版本**逐像素一致**。

## 对 gate 的启示
- **方向位掩码过滤可以几乎原样移植**：gate 已有 4KB bitmap/CellDirs/ intra-cell table，缺的是「(入口位置, 方向) → 可命中掩码」的编译期 LUT；与现有 u32 word 跳空叠加，属于纯收益。
- **Beam 优化与 gate 的 RenderScale 半分辨率方案同族**：gate 目前是固定半重采样（输出 640×360），beam 是「低分辨率取距离、全分辨率缩短行程」的两级版，且带无误差保证——是 1660 降档池里性价比极高的一项。
- 「跨层级 DDA」他悬而未决——gate 的 AABB slab 相对标尺（v3 修复）实际上就是这个问题的一种答案；反向看，gate 的跨 tile/slab 实现值得在 LUT 化后复测帧时，确认 slab 层没有被 brick 层优化反超。
- 他的 4³ brick 与 gate 的 16³ cell/512³ tile 粒度不同，但「mask + 数据段」的结构同构，LUT 规模可按 gate 粒度重估（16³ 入口 × 方向 = 表更大，需预算 VRAM）。
