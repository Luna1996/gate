# Devlog #28 - How I made voxels SHATTER on impact

- 视频: https://youtu.be/lsTHpbEN0dE （9:34，2025）
- 类别: 物理

## 一句话
破碎系统 = 「接触点冲量超阈值 → 删出裂纹体素 → 复用邻域断连器自动生成刚体」；核心洞见：判定用冲量不用力（力依赖 tick 率，冲量与帧率无关）。

## 内容要点
- **两部分架构**：①破碎事件生成——在刚体求解器里遍历接触点，取双方体素材质，**冲量超阈值即产生破碎事件**；②破碎模式应用——按事件选模式删体素成裂纹。
- **冲量 vs 力**（确定性关键课）：1kg 球 2m/s 撞墙反弹，动量变化 4 N·s 恒定；但「力 = 冲量/tick 时长」随 tick 率变（10ms→400N，5ms→800N）。**不用冲量会导致 30fps 与 60fps 玩家看到不同物理**。现实中材料断裂看最大应力（力），但没做形变模拟就用冲量近似。
- **冲量保留细节**：破碎接触点上要**减免施加的冲量**，物体在下一 tick 初仍带速度 → 石头能穿窗继续飞——动量守恒是真实感的关键。
- **应用的极简实现**（最聪明的部分）：代码库里本来就有「邻域断连器」（体素断开主网格就生成新刚体，砍树倒下靠它）。破碎只需**把裂纹体素设为空**，断连器自动把碎块变刚体——模块化、零新管线、还省性能（断连器反正要跑）。
- **裂纹模式可定制**（面向 modder）：布尔体素体积（true=删/false=留）即模式模板；材质绑「破碎表」（模式列表），按**冲量强度 + 随机数**选模式；每个模式内部生成 6 个朝向副本缓存；提供 Worley noise/平面切分的 stock 生成器；全部进 C# 公共 API。
- 顺带：碰撞检测器暴露给 C# → 禁止玩家把体素放在物理对象上（防搞崩模拟）；角色控制器动工。

## 对 gate 的启示
- **冲量/力之辨直接对应 gate 的固定 1kHz tick 语义**：gate 的一切模拟量都应定义在 tick 域（离散事件、拍数），任何「除以时长」的量都是帧率耦合陷阱——这条记入 gate 模拟层的确定性检查单。
- 「复用邻域断连器」= gate 的 flood-fill 连通性检测复用范例：破坏/断裂/电路断开共享同一条连通性管线，不另起炉灶。
- 「布尔体素模板 + 按强度选模式」的数据资产化思路与 gate 的主题资产/关卡数据组织风格一致，未来做可破坏物直接搬。
