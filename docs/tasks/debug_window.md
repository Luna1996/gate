## 任务背景
随着引擎功能的增加，调试功能也越来越多。
当前的DebugOverlay已经难以维系，需要重构。

## 顶层设计
1. 分两层：
   1. 单独的通用的Menu模块，提供容器和模块化控件，放在gate-ui还是单独模块你来决定
   2. gate-app中使用该容器，通过拼装控件、自定义控件实现针对gate-app的调试功能
2. 下文我如果说提取XXX，则表示需要将XXX提取成一个常量，放到单独文件中供我调整常量值
3. 需要引入FontAwesome图标库依赖
4. 新增gate-ui级通用控件：
   1. 文本输入框，支持纯文本模式，和数字模式，数字模式时支持直接点击拖拽设置数值
   2. tooltip，任何控件可以增加tooltip，当鼠标悬浮其上超过一定时间后展示tooltip
   3. 鼠标拦截，所有控件可以设置鼠标拦截
      设置后，悬停其上的鼠标所有事件（按键、移动、滚轮）均被拦截
      不会传递给其他UI或者3D场景
5. 菜单的层级状态，以及菜单控件的状态均可被序列化/反序列化（TOML格式），用于持久化存储
   并且要求在不依赖其他输入的情况下，单靠这个TOML文件，就可以完整重建Menu UI节点
   当然这不包括控件自定义按钮回调，回调在UI重建完成后通过统一接口挂上去即可
6. gate-app中的DebugOverlay改名DebugMenu，将上述TOML文件作为所有调试常量的初始值来源
   程序关闭前，将当前菜单状态序列化到TOML文件中，用于下次启动时恢复
   并且需要依照项目目前的默认初始值生成一版最初的TOML文件

## 通用容器
1. 最外层容器是一个带标题栏的窗口，提取标题栏高度20
   1. 窗口长宽可变，具体值完全由内容决定
   2. 标题栏从左到右为：返回图标按钮、当前菜单节点路径、重置位置图标按钮、收起/展开图标按钮
      1. 在根节点时，不展示返回图标，其他时候点击返回图标可以返回上一级菜单
      2. 菜单节点路径展示当前菜单节点的路径，例如：/debug/overlay
         根节点时，应显示为：/，路径过长时，中间用...省略（应该做成label控件基础能力）
      3. 重置位置图标按钮点击后，将窗口位置重置到默认位置
      4. 收起/展开图标按钮点击后，将窗口内容收起或展开，只显示标题栏
2. 当鼠标左键点击窗口标题或内容中任意未被其他可交互控件覆盖的位置时可以拖动窗口
   1. 这个Debug窗口被完全限制在系统窗口内，也就是说它的上下左右边界均不允许在系统窗口外
3. 标题栏下面就是菜单内容，存放在类似Android的ViewPager的容器中，支持向左或向右丝滑切换页面
   1. 当向左或向右切换页面时，会播放对应的切换缓动动画，提取动画时间
   2. 动画开始播放时，旧页面和新页面都处于实例化状态，从新页面完全不可见开始，
      他们侧边紧贴在一起播放向左或向右滑动切换的动画，直到旧页面完全消失
   3. 每个页面的宽度相同（提取宽度），长度可能不一样
   4. 动画播放过程中，窗口内容高度要设为两者中较大者，播完后设为当前页面高度
   5. 窗口的内容区域背景透明且clip子元素
4. 菜单内容本身是列表，提取默认列表项高度30，列表项间无border分割线

## 通用组件
通用组件指的是上述DebugWindow容器中的菜单列表单项，也就是说一个组件对应的是菜单中的一项
如无特殊说明，控件（算上padding/margin间距）需占满整个列表项（高和宽）
一行可以被分成三个部分，某些组件可以按需使用，以保持视觉上的整齐
左中右三部分，左右宽度相同，中间最宽。提取这两个值
控件如果要使用上述分割我会标记类似「左|中右」「左|中|右」「左中|右」

1. 子菜单，文字左对齐，右边有个向右图标
   整个列表项为一个按钮，点击后进入下一级子菜单，播放上述切换动画，并且修改标题栏路径
2. 按钮组，一个或多个按钮，每个按钮宽度均分
3. 滑动条，「左|中|右」，左侧名称，中间滑动条，右侧数值，左侧和右侧的宽度相等且固定，提取这个宽度
   右侧文字颜色暗一级
4. 切换组，多个无空隙并排按钮，宽度一致，点击后切换到对应状态
5. 开关项，「左中|右」，左侧文字，右侧toggle，左右对齐
6. 输入框，「左|中|右」，左侧文字，右侧输入框，输入框可能有多个，每个输入框宽度相等
7. 颜色选择器，「左|中|右」，左侧文字，中间HEX输入框，右侧显示一个对应颜色小方块
8. 纯文本
