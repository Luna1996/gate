## 2. 引擎总体架构

### 2.1 Rust 内核 + C 前端 API（#22，模仿 Unity）
- **Rust 内核**：体素/图形/物理，吃满 SIMD。
- **C 前端 API**：实体/业务逻辑/mod，**同地址空间动态链接**（wasm 独立地址空间的教训）；mod 作者与引擎作者用**同一套 API**。
- 最终前端语言为 **C#**（#24）：egui 绑定到 C#——`serde_generate` 出类型 + rustdoc JSON 遍历函数签名，自动生成 80% 绑定（省 2.5 个月手写）。
- **API 成熟度验收标准（他最自豪处）**：完整功能（如角色控制器 #29）只用公共 API 就能写出来。
- API 设计两原则：**最小化犯错路径 + 用类型系统静态强制约束**（#24）；不可变值类型 + 返回副本、从不原地修改，链式调用组织（#29）。

### 2.2 内部架构：geese 事件系统（#6/#9/#30）
- ECS 世界状态 + 事件系统混合：数据走 ECS 管道，反应式行为走事件，系统保留私有状态（GPU 句柄等）。
- geese 2.0：系统声明**依赖**构成 DAG，可互相**查询**（非只有事件广播）——低层 graphic system（分辨率/上下文）← voxel renderer / lighting renderer 各自依赖查询。
- 习语（#30）：**Store**（哑系统单例存纯数据）vs **System**（行为 + 私有状态）二分；事件集中放 `on::` 模块；系统 raise event（物理检出球出界 → graphics 监听持久化）。
- 泛型静态分发零成本抽象：`OctreeBuilder` trait 把数组转树/树合并/地形生成统一（#6）。

### 2.3 多线程：micropool（#27，延迟优先）
- 游戏要**延迟优先**调度，不是吞吐优先。
- 四要点：①**主线程亲自参与**并行迭代，不 idle 等待；②**根任务隔离带**——记录任务来源，worker 只窃取同一根任务的工作（物理永不顶掉世界生成）；③**全 atomics 无锁**：固定 job slot 数组 + `fetch_sub` 预约工作单元 + 未完成计数归零即完成；④位压缩占用掩码（64 个 bool 读一个 u64，高效迭代 0/1 段）。
- 支持 join 原语、后台任务、并行迭代器（paralite crate）；Miri 消毒器跑过；Tracy 验证 1000 盒子物理 12ms→8ms。
- 加线程池不行：主线程还要干别的 → 超订反而卡。

### 2.4 网络多人（#5/#9；ray marching 重写期间被砍待回归）
- 内部 **game server 线程 + 一切皆客户端**：主机玩家只是"另一个客户端"，单机/多人代码路径统一。
- 客户端预测：编辑先本地显示，服务器确认前可见（#9）。
- 体素同步：服务器自动追踪脏区域隐式推送，服务端编辑零网络代码（#9）。

## 3. 体素数据结构（最终：64-tree / con tree）

- **4³ 分裂 brick 树**（64 子块，非八叉树 2³）：层数更少、下钻读更少（#17）。
- **节点 = 64-bit occupancy mask（每 bit 一个子块）+ 数据段**：射线读一次 mask 进寄存器，之后位运算查子块空实，**最多 10 步不需要任何内存读**；bit=0 uniform 子块整格跳过/命中（palette 直出），bit=1 压栈下钻（#17/#18）。
- **撕掉法线字段**（#22）：腾出位宽；法线运行时隐式生成/上传烘焙（见 §5.4）。
- **编辑直接在稀疏组上操作**（#22）：区域 fill/copy + CSG（球/柱/环光栅化画入），~4-5k 行 Rust 实时执行；#26 重构修改算法与核心结构 → **2x 提速 + 可组合性大增**，体素对象与主网格同等编辑。
- **增量修改**（#3）：target/source 两棵树合并，同质区域短路，递归终止于单体素叶——编辑不重建整棵树。
- **连通性检测（CCL）**（#12）：**同质八分体整体当一个图节点** + 过程写稠密位图 O(1) 查成员；6 连通（不含对角）；从断口处局部 DFS，不全图重扫。
- 八分体坐标技巧（#3）：体素第 n 层八分体坐标 = 整数坐标二进制第 n 位的 3 个 bit，XOR/位运算 + SIMD 批量。

## 4. 渲染管线（最终：纯 compute ray marching）

### 4.1 主干
- **全屏 compute 逐像素 DDA** → 写 image → blit 上屏；图形 API = **Vulkan**（#23）。
- 遍历：chunk 窗口（AABB slab 相对定位）→ brick tree mask DDA（§3）。
- brick 内步进 **DDA 化**：存三轴 tMax，每步只更新最短分量 + 加法（纯加减，无乘除）（#18）。
- 跨 brick/跨层级仍是 ray-box 求交——他公开承认未解决（层次化 mask DDA 是社区后续答案）。
- **回归 ray marching 的动机**（#17）：逐体素独立颜色 + 逐体素法线是真实感根本；光栅化里每个独立体素都要生成三角形 → 效率崩。
- **集显策略**：不用混合管线，**直接降分辨率渲染**——「体素世界低分辨率反而可爱」（#17）。

### 4.2 性能三件套（#18，集显 120→60ms）
1. **brick 内 DDA 化**（120→100ms）：ray-box 求交 → tMax 加减。
2. **方向位掩码 LUT 预过滤**（100→80ms）：编译期对每种（进入位置 × 主方向组合）预计算「可能命中的体素掩码」；运行时 `occupancy_mask & dir_mask == 0` → 整个 brick 几条指令跳过。
3. **Beam 多分辨率保守起步**（80→60ms）：低分辨率先跑一遍（限制步进深度），全分辨率射线以**周围 4-6 条低分辨率射线的最小距离**为起点 → 平均行程大减。带保守性证明：**输出与非 beam 版逐像素一致**。

### 4.3 管线拓扑（#19 时代形态，#22/#23 沿用其结构）
```
beam 低分辨率预 pass
→ 主 pass（unlit 色 + 注册可见体素）
→ 直光（阴影射线）
→ 间接光（DDGI，#23 替代路径追踪）
→ 滤波/合成
→ 可选上采样 + AA（FXAA；MSAA 与手写深度互斥，#4）
```

### 4.4 材质 / 贴图 / 装饰（#22/#23）
- **上传时一次性烘焙**：算表面法线 → **tri-planar mapping** 贴高分辨率 PBR 纹理 → 法线+颜色烘焙进 GPU 侧体素模型并缓存（静态模型零运行时成本）。
- CSG 面置换（凹凸砖面）。
- 材质四分类：**电介质 / 金属 / 哑光 / 镜面**（+ 发光）（#23）；逐体素材质物理属性：密度/摩擦/弹性（#26）。
- **装饰层（decorations）**：草/叶 = 上传时按材质生成辅助 buffer，逐帧**预光栅化后合成**到 ray marched 结果上——风动的是装饰，体素不动；「树林/草丛不加 ray marching 命中代价」。
- **透明 = 吸收性透明**（玻璃/冰）（#22）。

### 4.5 LOD / 天空
- 八叉树层级遍历早停 = 天然 LOD（#2）；DDGI 探针 4 级 LOD（#23）。
- 程序化昼夜天空盒：太阳/月亮/星星 + 可调云量（#16）；DDGI 射线命中天空取天空色（#23）。

### 4.6 性能本质观（贯穿他全部优化决策）
- ray marching = **内存带宽瓶颈**（#4 实测：带宽多 1/3 → 快 30%）。
- 「消灭 buffer 读取和 for 循环是 GPU 侧最大收益来源」（#2，SVO 布局重排渲染耗时减半）。
- 「缓存又吃寄存器（同样糟糕）」（#17）——数据进寄存器一次、位运算用到底。

## 5. 光照（最终：直光硬阴影 + DDGI）

### 5.1 直接光
- 太阳**方向光硬阴影**：命中点向太阳投 1 条射线，不通即阴影——raymarch 已有，几乎白送（#2/#17）。
- 逐体素直光优化（#19，1660 Ti 省 1-2ms）：同体素多像素重复投射线 → 改**每体素 1 条**独立 pass + hashmap 复用。

### 5.2 间接光：DDGI（#23，gate P9 施工图）
- **探针放置**（烘焙，每模型上传一次）：网格 cell = 16³ 体素，每 cell 至多 1 探针带偏移；沿树 **BFS 找靠中心的最大空叶**（空 cell → 居中；半满 → 推向空边；全满 → 无探针）；再下采样出 4 级 LOD 探针。启发式：探针间距尽量大、离表面有距离。
- **防漏光**：探针额外存深度图（八面体映射 2D 纹理数组，每纹素同时存平均深度）；采样时「探针到墙的距离 < 探针到着色点的距离」→ 剔除。
- **每帧更新**：①活跃探针识别（本 cell + 6 邻接 cell 无体素 → 不活跃；GPU atomics 进 worklist）；②**每帧总射线数固定**摊给活跃探针（性能不随屏上探针数波动），方向用 Fibonacci 球；③样本转八面体映射存储。
- **无限反弹**：射线端点命中体素用**上一帧 DDGI 输出**着色；命中天空取天空色。
- **着色采样**：最近 8 cell → 三线性权重 × 视线可见性权重 × 前后位置权重。

### 5.3 发光体素
- 材质 emissive 分支直出（#19）：「撞到发光体素直接返回其颜色，三四行代码 = 面光源免费」——暗屋子点灯全靠它；传统光栅化是额外开销，ray marching 里零成本。

### 5.4 法线（最终：隐式）
- **运行时隐式生成**（近似算法），不存储进数据结构；静态模型**上传时烘焙**进 GPU 体素模型（#22）。
- 「逐体素法线 = secret sauce」（#17）：表面朝向决定明暗，让形状可辨、光滑不方块。

## 6. 物理（最终：v3，2025）

### 6.1 碰撞检测（#26）
- 体素分类 **corner / edge / face / interior**：沿某轴两侧都有邻居才不算 corner；仅一个轴两侧有邻居是 edge。只测 **edge-edge 与 corner vs (corner/face/edge)** → 接触点锐减（地面上的盒子只产生 corner 接触）。
- **角/棱取球面、面保持全平面**（他自己的折中发明）：Teardown 纯球近似旋转不变但球不填满体积（可见下陷 + 多余摩擦）；v2 的 bbox-AABB 平移比较**对旋转不变性错误**（法线算错 → 抖动）。折中方案数学量与球法相当、伪影消除。
- 快速路径：把一方体素中心**变换到对方坐标系**查最近 8 体素是否有实心（等效小球，副作用是更易滚动——观感反而自然）（#20）。
- SAT 线性性质（#11）：体素全网格对齐 → 只对「原点单位体素」算一次投影区间，之后每对体素碰撞仅 1-2 次矩阵乘；八叉树大空区整块免检；投影区间中央间隙 = 最小分离距离（可预测碰撞防穿透）。

### 6.2 求解器（#26）
- **TGS（temporal Gauss-Seidel）+ warm starting**：加力 → 解速度约束 → 更新位置的内循环多次迭代，**复用已有接触、不重跑碰撞检测**。
- 关键洞察：**先解速度约束再积分位置**（split impulses 浮点精度致静止盒子振荡）。
- **warm starting**：以上一帧接触力为初值；体素场景天然优势——**用「两个碰撞体素的坐标对」作 hashmap key** 关联帧间接触（常规引擎要造唯一 contact ID）。
- 成绩：杠杆/扭矩正确；0.5m 盒子叠 6 层不塌；杂乱堆叠不爆炸不嵌墙。
- 手写无锁多线程调度 + 接触图着色（#26/#27）。

### 6.3 结构性系统
- **睡眠**（#13）：「自己上 tick 没变 + 邻近对象最近几 tick 没变 → 结果必然相同 → 整个跳过」。砍 10-20 棵树后碰撞 14-15ms 线性回落。
- **断连 → 新刚体**（#12）：CCL（同质八分体单节点 + 位图）从断口局部 DFS；砍树倒下、破碎共用同一条连通性管线。
- **破碎**（#28）：接触点**冲量**超阈值（**不用力**——力 = 冲量/tick 时长随帧率变，冲量恒定 → 30fps 与 60fps 玩家看到同一物理）→ 按材质「破碎表」选模式删裂纹体素 → **复用断连器**自动生成刚体（零新管线）。冲量保留细节：破碎接触点上减免施加冲量 → 石头穿窗继续飞（动量守恒）。模式 = 布尔体素模板 + 按冲量强度/随机数选择 + 6 朝向副本缓存 + Worley noise stock 生成器，全进公共 API。
- **Despawn 融合回地形**（#13）：碎屑久置后仿射变换重新光栅化融合进主体素网格；**等玩家背过身去才执行**——不观察就不突兀。

### 6.4 角色控制器（#29，运动学）
- 选**运动学**而非刚体：动作用碰撞查询自定义（上台阶这类非牛顿行为好加），且可跑客户端（操控需即时响应）。
- 移动循环：碰撞检测拿接触法线 → 每接触视作平面，把期望速度**裁剪到与所有平面相切或背离** → 沿裁剪速度 sweep hitbox（略小于 1 体素步进）→ 撞到新东西再裁剪 → 循环到 time step 结束。
- **上台阶**（Quake 取经 + 两改造）：①不只试整档 step height，**按 1 体素增量试多档**（避免过冲撞门框）；②**找到首个保持全速的可行解即停**（不等最优）。下台阶免费：每条路径结尾向下探一整档贴地行走。
- **防晕相机**：垂直位置建模为**临界阻尼弹簧**（阻力系数保证临界阻尼 → 永不过冲、指数收敛）。
- 材质交互复用刚体系统（脚下体素摩擦/弹性）。

## 7. 地形生成（最终）

- **管线即数据**（#14）：生成器 = 低层指令列表（向量加减乘/随机数）→ 字节码可序列化、运行时可改 → 每指令一段 WGSL 拼成完整 compute shader → GPU 生成 → 读回 CPU 组树。未来做节点编辑器/语言前端。
- **区间算术跳同质区**（#14）：管线是纯函数（位置→实数→>0 空 / ≤0 实）；对输入区间预测输出区间 → 输出区间整段同号 → **整块 16³ 直接赋同值**（地表 chunk 只算 20-30%，天空/地下近乎 100% 跳过）。两份 shader：区间版 + 逐体素细采样版。
- **含 3D 模型的区域**（#14）：数学预测失效 → 距离场判同质：预计算 16 倍降采样 DF，`DF(角点) > 盒边长` ⇒ 整盒同质（取角点值），否则逐体素。
- **API 设计**（#25）：曲线对齐 Minecraft（大山丘/沟壑/3D 悬垂）；高性能可扩展，目标是**用户写自己的生成器**；生物群系（草色/沙/雪）+ 地表物件（树/石/花）。
- 网络侧：服务端**按 LOD 粒度直接生成**（非先全质量再下采样）+ 编辑脏区沿 LOD 树向上标记 + 请求时只重组脏子八分体（#16）。

## 8. Tricks 与工程教训清单（跨领域）

**GPU / 数值**
- 浮点射线坑（#1）：相邻体素**乒乓死循环** → 强制每次至少前进一步；**丢失当前体素** → 位置 snap 吸附进体素。
- 四元数乘法不交换（#12，调了三周的「幽灵自转」）→ 任何非对易结构在代码里**显式标注乘法顺序**。
- enum 构造 UB（#31）：在范围检查**之前** unsafe 构造 enum，编译器据 soundness 反推检查恒真并优化掉 → **先校验后构造**；升级编译器后行为突变先怀疑 UB。
- 小编辑合批（#10）：引擎「吃大不吃小」；高频小更新（雪、粒子沉积）攒 20-30 个一次提交。
- 坐标对作 hashmap key（#26/#28）：凡「帧间/tick 间持续关系」的缓存都可用。
- SIMD 批量：八分体坐标提取（#3）、八叉树→包围盒 VBO 生成 20ms→6ms（#33）。
- GPU 显存统一管理（#7/#33）：全部体素数据塞 1 个大 buffer + 少数大纹理，页式分配 + 64 页一组位运算找连续空页。
- 冲量不用力（#28）：一切模拟量定义在与帧率/tick 率无关的域。

**工作法 / 调试**
- 三周 bug 诊断法（#12）：①单轴化降维（关掉其他轴）→ ②各阶段间插打印逐段核对 → ③找不变量矛盾（两物体角速度相同转向相反 → 锁定转换代码）。
- Tracy profiler（#27）、RenderDoc 单步 GPU shader（#1）。
- **先 2D 后 3D**（#20/#25）：数值算法先在 2D 玩具引擎（Rigid Pixels）定算法再进主引擎。
- 「玩家背身时执行重操作」（#13）：LOD 重构/融合/重算选时机。
- kanban 看板管理任务（#10）；cargo workspace 拆分治冷编译 30s+（#8）。

**API / 架构**
- 最小化犯错路径 + 类型系统静态强制（#24：ImGui 三宗罪 = unsafe + 全局状态 + begin/end；egui 闭包作用域式是标杆）。
- 不可变值类型 + 返回副本 + 链式调用（#29）。
- 「只用公共 API 能实现完整功能」= API 成熟度验收标准（#29）。
- Store（纯数据）/ System（行为）二分；读侧查询走依赖、写侧通知走事件（#30/#9）。
