# Taste
- Prefers changes to be left uncommitted at the end of a task (working-tree diff for their own review), not auto-committed. Confidence: 0.6
- Prefers NOT to reformat or lint-fix pre-existing code outside the scope of the change: when `cargo fmt --check` / `clippy -D warnings` are already red on untouched files, keep the diff focused instead of doing a repo-wide reformat. Confidence: 0.7
- Wants their local environment/config restored after benchmarking (e.g. revert `video/vsync` back to its original value once measurement is done). Confidence: 0.6
- Documents performance investigations as dated rounds in `docs/editable-gigavoxel.md`, following the existing table format and methodology. Confidence: 0.65
- Benchmark methodology: same-session A/B at the same camera position and world state; compare GPU per-pass ms (`gate_dda_trace` etc.) rather than fps, because vsync masks framerate; use a dedicated `GATE_BENCH=<mode>` benchmark the repo designates per investigation (e.g. `static`, or the newer `fly` for forcing streaming/traversal of new chunks) with `--features profile`, and take means over a steady window rather than a single instant. Confidence: 0.65
- Prefers temporary diagnostic probes/instruments to be gated behind a `const` (zero cost when disabled, e.g. `LOD_DIAG = 0`) and removed or disabled after measurement, rather than deleting the diagnostic machinery. Confidence: 0.55
- Communicates in Chinese (Simplified) — including terse one-line bug reports — and expects replies (and doc/code comments) in Chinese too. Confidence: 0.6
- Reports visual/rendering bugs by attaching a screenshot plus a terse description of the on-screen symptom (e.g. "看起来就像pixel dithering"), often validating that the previous fix worked before reporting the next defect, and expects feature-toggle isolation as a triage step (e.g. "关闭GI时没有"). When asked to isolate, actually runs the toggles one at a time and reports each outcome with a discriminating qualifier rather than a plain on/off verdict (e.g. "完全消失（而不是变小）" vs "纹路换样子、更明显"), so the responsible rendering layer can be pinned down. Confidence: 0.7
- Performance acceptance bar is goal-dependent: for perf-focused work both the dynamic (`fly`) and static (`static`) benchmarks must reach 100+ fps to count as passing; for a deliberate visual-quality goal they relaxed the floor to a stable ≥60 fps, reserving frame-time headroom for upcoming gameplay features (e.g. water physics, rigid bodies). Confidence: 0.55
- Sets visual-quality targets by pointing at external reference implementations (e.g. a competitor voxel engine's devlog video) and expects the agent to research that technique and quantify the gap against it, instead of only tweaking the existing path. Confidence: 0.55
- Wants performance gains via genuine algorithmic optimization ("真优化"), NOT by lowering quality settings — explicitly rejects meeting a perf target by changing the quality config (render scale, GI, shadows, etc.), and applies the same rule to bug fixes: fix quality/visual defects without harming performance and without changing quality settings. Quality preset must stay fixed. Scope: this holds for perf work and bug fixes; when the goal is deliberately *raising* visual quality (e.g. matching a reference look), they do permit recalibrating quality presets upward within an agreed frame-time budget. Confidence: 0.85
- For large, architecture-level rendering work (e.g. a full GI overhaul), wants the agent to work in plan mode: produce a written plan that lays out the current-vs-target gap and the options, get it approved, and only then implement — rather than diving straight into edits. Confidence: 0.55
- When a reference-matching goal isn't converging through incremental tweaks, is open to wholesale re-implementing the reference technique ("照抄"), but requires any adopted/borrowed technique to be adapted and validated against the engine's core constraints — specifically the streaming large-world design and fast voxel-editing responsiveness. Confidence: 0.5
- States hard engine constraints upfront and expects them to prune the solution space, not be worked around: e.g. the scene can contain an unbounded number of emissive voxels, so approaches that need a bounded/partially-enumerated emissive-source table (emissive NEE, per-light sampling) are ruled out; and raising the GI quality preset drops frames, so quality-scaling is not an acceptable lever. Confidence: 0.55
- Before signing off on a proposed technique or optimization, wants its cost laid out as concrete numbers on both axes — time (per-frame / GPU pass ms, ray or sample budget) and space (VRAM/RAM footprint) — not qualitative adjectives; asks for the breakdown when a proposal only describes the benefit. Confidence: 0.55
- Judges rendering quality against a real-game acceptance bar, not against "better than the last iteration": temporal/appearance artifacts such as GI instability, slow convergence (especially while the camera moves), or full-screen flicker triggered by world edits are called out as flatly unacceptable in a shipped game ("这种效果基本不可能在游戏中接受"); also treats a fix that only yields "a slight improvement" as unresolved rather than a win (e.g. "稍有改善，但还是很严重"). Confidence: 0.6
