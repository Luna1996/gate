# Taste
- When asking to remove a feature, means total removal with no leftovers: "把这套东西以及相关代码全部删掉，不是我想要的". Expect the whole feature (functions, constants/toggles, every call site, README/doc mentions) gone, call sites reverted to the prior simple path, a repo-wide grep proving no residue, and a compile/test run to confirm. Reverting a call site to the simple original implementation (plain bilinear) is the accepted substitute; do not leave a feature flag or a stub behind. Confidence: 0.7
- The gate workspace is release-only for builds/tests: plain `cargo test -p gate-render --test wesl_package` fails, so always pass `--release`. Use the targeted per-crate test (e.g. `cargo test --release -p gate-render --test wesl_package`) as the verification step for WESL/shader edits. Caveat: that test validates only a hardcoded list of entry points in `tests/wesl_package.rs` — a newly added WESL entry point must be appended to that list or it is never actually compiled/validated, so a green test run says nothing about whether the new pass builds. Confidence: 0.7
- Prefers changes to be left uncommitted at the end of a task (working-tree diff for their own review), not auto-committed. Confidence: 0.6
Joins the defect's *scope* to the report and expects the fix to address that exact scope rather than the neighbouring symptom you assumed: after a fix is accepted, a follow-up such as "颜色变了，但还是不稳定" means (a) the color/brightness **did** change — the visible shift is real and stays, treat it as an accepted, deliberate change — but (b) the *instability* (GI flickering with small view changes) is still present, so the residual is the same underlying artifact and must be chased down to its structural cause. Phrased terse, with a bare screenshot pair attached and no diagnosis offered. Confidence: 0.6
- Any derivative/computed quantity feeding a shading or lookup decision must itself be **stable** before the decision built on it can be trusted: accept a fix that removes one hard discontinuity only to have the next round fail on a second, lower-level hard switch in the same code path (here: a `argmax`/dominant-axis pick over a blended normal, which flips between two axis-aligned planes on a bevel and silently changes the entire candidate set for a whole region). When a two-stage or multi-branch criterion is introduced, audit the *inputs to the branch* for their own discrete flips before adding more stages. They also ask, unprompted, which fix direction was cheaper when two remain (e.g. tuning a threshold constant vs. removing the flip) — and the direction that requires sacrificing an established design invariant must be raised as a question first, with the cost named, not silently taken. Operational rule that follows: each round that removes one flip exposes the next remaining discrete decision in the same path — so instead of patching one per round, sweep the whole function and convert every boolean/thresholded decision into a continuous weight (keep only the hard predicates that are strictly required for correctness, e.g. "same object" to prevent bleed), delete the now-unused threshold constants, and let the weighting subsume the old special case (a single-axis normal then reproduces the axis-only filter naturally). Only when no discrete decision remains should the residual be attributed to sampling density/architecture, and that conclusion should be offered as a short feasibility write-up (why unreachable, what architecture change it needs) instead of another filter tune. Confidence: 0.6
- Prefers NOT to reformat or lint-fix pre-existing code outside the scope of the change: when `cargo fmt --check` / `clippy -D warnings` are already red on untouched files, keep the diff focused instead of doing a repo-wide reformat. Confidence: 0.7

- WESL shader work in `gate` is coupled to Rust-side binding layout and buffer allocation, so a WESL-only edit/revert is never a complete change. A new `bindings.wesl` entry (e.g. `wal_vox`, `wal_cell`) has no meaning without the matching `gate-render/src/{gi,dda,upload}.rs` layout and buffer allocation, and a renamed WESL entry point (e.g. `gi_wal_pool` → `gi_wal_pool_r` with an added radius/age param) must be reflected in every import *and* call site. The working tree can therefore sit in a "half-migration" state — a module expecting new bindings and new signatures while `bindings.wesl` and HEAD still carry the old set — in which the build fails on undefined symbols for reasons unrelated to whatever the agent just changed. Rule: when the package test fails on undefined symbols, enumerate every mismatch across HEAD / working tree / stash *before* editing anything, cross-reference the same files at each version to see which pair is self-consistent, and never invent a binding definition to silence the error — recover the paired change (it is often sitting in a stash or was never saved). Report the inconsistency as the user's own uncommitted work and let them decide. Two refinements from later rounds: (a) verify the stash is not an *abandoned* design before mining it for the paired half — the user keeps superseded work around and kills it in one terse line ("emit_nee 是已经废弃的方案"); that ruling is hard and final, so the stash must be dropped from the analysis entirely and the working tree re-derived on its own (never offer the deprecated design as a candidate path again). "Which version is still live / what is abandoned?" is the *one* question in this area the user answers instantly and precisely, unlike micro-parameter questions that get "我不知道" — so ask it early and don't re-ask anything else. (b) if a symbol has *zero* matches on the Rust side (not merely a stale layout), the WESL module is a forward-looking draft whose Rust half was never written, not a lost paired change — stop patching, say so plainly, and offer to preserve the draft (copy aside) before reverting to a compiling baseline, rather than guessing buffer sizes and binding groups. When a step is blocked on information only the user holds, ask that one question and then hand back a numbered set of concrete options with a single stated recommendation (including "preserve the draft aside, then restore a compiling baseline") instead of another speculative edit round.
