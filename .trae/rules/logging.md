# 日志：能不打就不打

日志是**最后的**手段。落笔前先问一句：这个信息能不能用返回值 / 类型 / 断言 / 测试表达？能就别打。

- **只留关键符号、关键信息、关键动作**，不写完整句子：去掉主语、连词、礼貌用语，以及「已经」「成功」「开始了」这类词
- 形态是 `<东西> <符号> <值>`：`→` 表动作、`!` 表失败、`[]` 表标签、`vx`/`ms` 表单位
  - ✅ `info!("size → 8")`、`info!("EDIT[place] 27vx @(12,4,9) 3.1ms")`
  - ❌ `info!("笔触大小 → {} vx（跨度 {}）", size, span)` —— 括号里的解释属于注释，不属于日志
- **同一件事只在一处打**。启动 / 初始化 / 编译期这类一次性提示用 `*_once!`
- **分级按"实际触发频率"定，不按"在哪个系统里"定** —— 一个系统每帧都跑，不等于它的日志每帧都打：
  - `info!`：**离散的用户动作**（一次落笔、一次切模式、一次改档位）+ 失败与降级 + 启动里程碑
  - `debug!`：每帧 / 周期触发的东西、诊断细节、常规成功动作的内部步骤（一次成功的读写、一次正常派发）
  - 判不准就问"默认 `info` 过滤下，这条一分钟会刷几行"——大于一行就降级
- **必须留下的只有两类：失败与降级** —— 且要带**原因**：哪个输入、撞了哪个上限、回落成了什么。**已登记的验收口径（某里程碑靠某行日志取证）不许降级**
- **不动**：`tracing` / Tracy 的 zone 名与 pass 名（那是性能剖析口径，不是日志）、`panic!` 与 `expect()` 的文案、`assets/locales/*.toml` 的 UI 文案
- 新增之前先找同类：能并进已有那一条，就不再开一条

`INFO` 只服务"排查当前这一次运行"。运行轨迹用 `debug!`，性能用 `--features profile` 下的 Tracy。
